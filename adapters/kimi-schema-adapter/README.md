# Delta Kimi schema adapter

This loopback adapter preserves the existing Kimi transport and corrects one
Delta tool-schema incompatibility. In `delta_settings`, an array branch exactly
equal to `{"type":"array","items":true}` becomes
`{"type":"array","items":{}}`. Other schemas and accepted JSON values are
unchanged. Requests requiring no correction retain their original JSON bytes.
When correction is required, every numeric literal retains its original value
and representation, including precise decimals, exponents and signed zero.

The source and its original regression tests were brought into this repository
from the locally installed adapter. Private state, settings, credentials, logs
and launchd files are not part of this directory. The repository copy adds
request timing diagnostics and lossless numeric serialization; importing it does
not change the running service.

## Transport and access

The listener binds only to `127.0.0.1`. Both the chat POST route and the model
discovery GET route require the private capability path and provider Bearer
authorization. Unexpected Host values, browser Origin headers, query parameters
and unrelated routes are rejected. The upstream routes are fixed Kimi HTTPS
endpoints, TLS is verified and redirects are not followed.

End-to-end headers and provider response bytes are forwarded, including compressed
bodies. Response bytes stream as they arrive. An interrupted response closes as
an error rather than a successful truncated response. The adapter retains the
existing 30-second socket-connect timeout, with no application-wide generation
deadline or response-read timeout. It does not retry or select another provider.

## Timing diagnostics

Each authorized request receives a random 128-bit correlation ID generated by
the adapter. JSON diagnostic lines record a UTC timestamp, the request ID, the
event and phase, total elapsed milliseconds, and elapsed milliseconds within the
phase. Fixed events identify request acceptance, upstream start, connection
creation or reuse, sent request headers, received response headers, first response
bytes, completion, rejection, error and caller cancellation.

These records distinguish connection setup, waiting for the initial upstream
response, and response streaming. An error records only its exception class name.
The optional HTTP status and schema-correction count are numeric. Logs contain no
capability path, URL, provider request ID, request/response headers, prompt,
response body or credential. The random ID is local diagnostic metadata; it is
not forwarded to the provider or supplied by the caller.

Use the event sequence to locate a delay. A caller cancellation while the phase
is `response_headers` means the adapter had sent request headers and had not
received upstream headers. This interval includes any remaining request-body
upload. An error in `response_stream` means headers were received but
the stream or downstream write did not complete. These observations do not
establish whether a provider accepted or billed a request. The review workflow
still requires terminal native evidence before its bounded retry.

Startup retains its existing human-readable loopback status line. HTTP access
logs remain disabled. Failure to write diagnostics does not alter the forwarded
response.

## Local verification

Python 3.12 or newer is required. `uv.lock` pins the existing aiohttp dependency.
From this directory:

```sh
rtk proxy uv run --locked python -m unittest -v
rtk proxy ruff check adapter.py test_adapter.py
rtk proxy ty check --python .venv/bin/python --python-version 3.12 --error-on-warning adapter.py
```

The tests use synthetic credentials and local upstream servers. They cover the
exact schema rewrite, unchanged unrelated requests, access boundaries, streaming
and compression, redirects, TLS failure, private state, CLI startup/shutdown,
request correlation, connection reuse, cancellation before response headers,
stream interruption and content-free error logging. They do not call Kimi or
prove native Delta review execution.

For an isolated local run, use an unused port and a private state directory whose
parent already exists:

```sh
rtk proxy uv run --locked python adapter.py --port 0 --state /absolute/private/adapter-state
```

The state directory contains the private capability and endpoint metadata. Keep
it out of support reports and version control. Do not run a second instance on
the installed service's port or state directory. Deploying this repository copy,
restarting a service or changing Delta provider settings is a separate operation.
